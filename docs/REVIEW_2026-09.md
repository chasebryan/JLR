# Adversarial review of the first implementation

After the first implementation was merged (pull request 3) it was reviewed by five independent reviewers, each covering one
area, and every finding was then attacked by three skeptics whose job was to refute it. Thirty-five findings survived.
Several reviewers found the same defect from different sides, so the distinct problems are fewer: the exec gate failing
open on measurement errors, the exec gate missing later mounts, `jlr run` holding the ledger lock, a torn checkpoint log,
and the revocation target rules were each reported two to four times.

This document records what each finding was and what was done about it. Severity is the reviewers' own.

| Severity | Count |
|---|---:|
| high | 11 |
| medium | 16 |
| low | 8 |

Dispositions:

- **Fixed:** the defect is closed and a test that fails without the fix backs it. Where a fix is mutation-checked, removing
  it makes the named test fail.
- **Mitigated:** the attack is bounded or made expensive but not removed; the remaining gap is stated.
- **Fixed, with limits:** the reported attack is closed and a related boundary remains, stated in the row and in
  [SECURITY_BOUNDARIES.md](SECURITY_BOUNDARIES.md).

## Findings

| Id | Severity | Finding | Disposition |
|---|---|---|---|
| crypto-ledger-01 | high | Torn checkpoints.log tail is ignored, not repaired; the next checkpoint permanently corrupts the log and bricks the ledger | **Fixed.** `a_torn_checkpoint_tail_is_quarantined_and_does_not_brick_the_ledger`, `a_failed_append_leaves_no_bytes_behind` |
| crypto-ledger-02 | medium | Replay recomputes the Merkle root from scratch for every checkpoint (O(events x checkpoints)); the 'fast path' is slower than full verification and the ledger size is attacker-controlled | **Fixed.** `prefix_roots_are_constant_time_lookups_that_match_the_recursive_definition` |
| crypto-ledger-03 | medium | `jlr ledger verify --checkpoint` verifies through a read-write, key-holding Engine::open: it fails on read-only storage and mutates the evidence it is verifying | **Fixed.** `jlr ledger verify` calls `verify_ledger_at`: no key, no lock, no writes |
| crypto-ledger-04 | medium | Attacker-controlled file names are stored verbatim in signed ledger events and printed raw by `jlr ledger log`, allowing forged rows and terminal escapes | **Fixed.** `sanitize` in the model crate, applied when events are written and wherever the CLI prints; `attacker_chosen_names_cannot_inject_control_characters_into_the_ledger` |
| policy-engine-01 | high | Attacker-triggerable measurement errors turn the exec gate fail-open, so unknown, tampered or revoked binaries run under enforcement | **Fixed.** Unmeasurable files are decisions: `a_file_that_cannot_be_measured_is_a_denial_not_an_internal_error`; QEMU `enforce unmeasurable: BLOCKED`. Same root cause as measure-cell-01, boot-gate-01, cli-invariants-01 |
| policy-engine-02 | medium | Approvals and baselines are not bound to the ledger, so a withdrawn or superseded signed approval or baseline can be replayed | **Fixed.** Approvals and baselines count only if they are the latest ledger override: `a_withdrawn_approval_cannot_be_put_back_from_a_copy`, `a_superseded_baseline_cannot_be_restored_from_a_copy`. Baselines enrolled earlier must be re-enrolled |
| policy-engine-03 | medium | Degrade-on-change and revoke depend on two unauthenticated caches (path index, epn objects) and silently do nothing when they are missing or truncated | **Fixed.** `losing_the_path_index_does_not_hide_that_a_trusted_file_was_replaced`, `losing_the_object_store_still_degrades_a_trusted_file_that_changes`, `a_truncated_object_is_rewritten_the_next_time_the_artifact_is_seen` |
| policy-engine-04 | medium | Governance-plane state is attacker-growable without bound and every gate decision costs O(ledger size) plus a full index rewrite | **Mitigated.** A repeat exec writes nothing (`a_repeat_exec_decision_for_an_unchanged_file_writes_nothing`), caches and tallies are bounded, each user has a slow-path budget, and open is O(1) per checkpoint. **Not eliminated:** each unique unknown executable still adds two objects and two events, and every uncached decision still opens the engine (about 90 ms at 6,000 events). The rate is now bounded per user; growth is not capped |
| policy-engine-05 | medium | Revocation entries are never validated or canonicalised, so a malformed target is signed, ledgered and reported as done while matching nothing | **Fixed.** `revocation_targets_are_validated_and_put_in_the_form_the_matcher_compares`. Signer revocation is accepted but inert until an adapter records signers; the CLI says so |
| policy-engine-06 | low | Ledger events are made durable before the objects they name, and the index before the events (I-04 ordering not held in the default sync path) | **Fixed, untested.** The index is saved only after the ledger is durable, and an event that names objects waits for them. There is no crash-injection test; the order is by construction |
| policy-engine-07 | low | Incremental scans reuse rows without re-evaluating, so states stay ADMITTED after approval or baseline expiry or a policy change; gate verdicts outlive approval expiry by up to an hour | **Fixed.** `an_expired_approval_is_noticed_by_an_incremental_scan`, `a_new_policy_epoch_re_decides_files_an_incremental_scan_would_skip` |
| policy-engine-08 | low | Attacker-chosen file names reach operator terminals unsanitised (escape and newline injection can forge decision output) | **Fixed.** See crypto-ledger-04; scan, explain, log and revoke output is escaped |
| measure-cell-01 | high | Attacker-triggerable measurement errors (oversize, file changing) turn an exec denial into fail-open | **Fixed.** Duplicate of policy-engine-01 |
| measure-cell-02 | medium | measure_file's 'changed while reading' guard ignores ctime, so a file owner can obtain a digest of content that is no longer in the file | **Fixed.** `an_edit_that_restores_mtime_is_still_detected_because_ctime_cannot_be_restored`, `a_file_that_keeps_changing_is_reported_not_measured` |
| measure-cell-03 | medium | Workload inherits the report pipe and every non-CLOEXEC descriptor of the launcher; no descriptor sweep before exec | **Fixed.** `descriptors_left_open_by_the_launcher_do_not_reach_the_workload`, `the_report_pipe_is_not_open_in_the_workload` |
| measure-cell-04 | medium | walk() opens files without O_NOFOLLOW/O_NONBLOCK after an lstat, so a swapped entry hangs or redirects the scanner | **Fixed.** The walk opens with `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC` |
| measure-cell-05 | low | landlock-net can never be reported active, so every DESTINATION_ALLOWLIST cell is refused with a false reason | **Fixed.** `the_destination_allow_list_is_enforced_by_landlock_and_reported_as_active` |
| measure-cell-06 | low | syslog(2) is not denied, so a workload can read the host kernel ring buffer when kernel.dmesg_restrict=0 | **Fixed.** `the_host_kernel_log_cannot_be_read_from_inside_a_cell` |
| measure-cell-07 | low | FS_READ/FS_WRITE grants for any path under /tmp are silently dropped because the private-root tmpfs hides host /tmp before the path is checked | **Fixed.** `a_grant_below_tmp_is_applied_even_though_the_root_is_assembled_in_a_tmpfs`, `a_grant_that_cannot_be_applied_is_reported_and_makes_the_report_partial` |
| boot-gate-01 | high | Exec gate fails open on measurement errors that the executing user controls (size limit, mtime race) | **Fixed.** Duplicate of policy-engine-01 |
| boot-gate-02 | high | Only file systems mounted before jlrd started are gated; any later mount is invisible to the gate | **Fixed, with limits.** Mount-table watcher: QEMU `late mount stranger: BLOCKED`. Not covered: mounts in another mount namespace, and a window of a few milliseconds after a new mount (SECURITY_BOUNDARIES 5) |
| boot-gate-03 | high | Any local user can stall every exec on the machine: serial FIFO loop, expensive cache misses, no rate or size bound | **Mitigated.** Per-user slow-path budget, `O_NONBLOCK` reads so a FIFO cannot hang the gate, bounded caches, unmeasurable denials cached for seconds. The gate is still one thread and root is not throttled |
| boot-gate-04 | medium | Ledger lock contention makes the gate fail open (unrecorded); `jlr run` holds the lock for the whole workload | **Fixed, with limits.** `run_detached_gives_the_ledger_back_while_the_workload_runs`. Contention beyond the wait still follows `--fail-closed` and is recorded as DEGRADED when the ledger can be opened to record it |
| boot-gate-05 | medium | A second attached disk with a /jlr tree defeats the rollback floor, not just availability | **Fixed, with limits.** `a_second_disk_with_an_older_release_cannot_downgrade_the_machine`, `a_pinned_boot_never_uses_or_mounts_another_disk`. Unpinned boots still trust whatever media is attached; the pin file path in the initramfs is not covered by a QEMU test (the command-line path is) |
| boot-gate-06 | medium | Boot state error paths fail toward downgrade and permanent brick (any read error resets the floor; any I/O error marks a slot bad forever) | **Fixed.** `an_unreadable_boot_state_stops_the_boot_instead_of_resetting_the_floor`, `a_write_protected_medium_boots_its_proven_slot_and_skips_an_unproven_one`, `only_content_that_is_provably_bad_retires_a_slot`, `an_interrupted_rename_does_not_reset_the_floor` |
| boot-gate-07 | low | Cached ALLOW verdicts outlive approval and baseline expiry by up to an hour | **Fixed.** Cached verdicts expire at the earlier of the evidence age limit and the approval or baseline expiry |
| boot-gate-08 | low | Attacker-chosen executable paths are logged and displayed with control characters intact | **Fixed.** See crypto-ledger-04; gate log lines use the escaped path |
| cli-invariants-01 | high | Exec gate fails open on measurement errors that the executing user controls (mtime touch loop, or a file over 512 MiB) | **Fixed.** Duplicate of policy-engine-01 |
| cli-invariants-02 | high | Exec gate marks only the file systems mounted when jlrd started; later mounts are never gated | **Fixed, with limits.** Duplicate of boot-gate-02 |
| cli-invariants-03 | high | `jlr run` holds the exclusive ledger lock for the workload's whole lifetime, so the exec gate stalls 3 s per exec and then fails open, and revoke/policy changes are blocked | **Fixed.** Duplicate of boot-gate-04 |
| cli-invariants-04 | high | A torn tail of checkpoints.log is ignored at open but never repaired; the next checkpoint is appended after the garbage and the ledger becomes permanently unopenable | **Fixed.** Duplicate of crypto-ledger-01 |
| cli-invariants-05 | high | A cell workload shares the operator's controlling terminal, and seccomp does not restrict tty ioctls (TIOCSTI keystroke injection out of CELL-0) | **Fixed.** `the_workload_has_no_controlling_terminal_even_when_started_from_one`, `a_terminal_cannot_be_used_to_type_into_the_operators_shell`, both run under a real controlling terminal and mutation-checked |
| cli-invariants-06 | medium | The policy epoch floor is parsed back out of free-text event detail; a policy name containing `epoch=` permanently bricks the state directory or lowers the floor | **Fixed.** `the_policy_epoch_floor_ignores_prose_an_author_controls`; policy and tier names are restricted to `A-Za-z0-9._-` |
| cli-invariants-07 | medium | Every uncached exec by any user drives unbounded, superlinear governance state growth, and attacker-chosen path text is printed raw by `jlr ledger log` | **Mitigated.** Duplicate of policy-engine-04 |
| cli-invariants-08 | medium | Revocation targets are not validated or normalised; the natural copy-paste digest never matches, and signer revocations can never match anything | **Fixed.** Duplicate of policy-engine-05 |

## What this review did not cover

The reviewers read the code and ran probes; they did not fuzz the parsers, model the kernel, or test on hardware other
than the development machine. A clean list here is a statement about what was found, not a proof that nothing remains. The
list of open boundaries is [SECURITY_BOUNDARIES.md](SECURITY_BOUNDARIES.md) section 2.

## Process notes

- Each fix that closes a security property was mutation-checked: the fix was reverted and the test confirmed to fail. Two
  tests written first were found to pass without the fix (a terminal test that ran without a controlling terminal, and a
  TIOCSTI test whose result the kernel decided on this host) and were rebuilt to run under a real pseudo-terminal.
- Findings that were duplicates were fixed once, at the cause.
- Decisions that changed as a result are ADR-033 to ADR-039 in [DECISIONS.md](DECISIONS.md).
