# Adversarial review of the first implementation

After the first implementation was merged (pull request 3) it was reviewed by five independent reviewers, each covering one
area, and every finding was then attacked by three skeptics whose job was to refute it. Thirty-five findings survived.
Several reviewers found the same defect from different sides, so the distinct problems are fewer: the exec gate failing
open on measurement errors, the exec gate missing later mounts, `jlr run` holding the ledger lock, a torn checkpoint log,
and the revocation target rules were each reported two to four times.

The fixes were then reviewed the same way (sections "Review of the fixes" and "Review of the second round of fixes"): 61
findings reported and 57 confirmed against the first fix commit, then 36 and 35 against the second. Each round found real
defects in the previous round's fixes and in the tests that were meant to prove them, and the results are recorded here.
Returns diminish (the last round's findings were mostly medium and low) but were not zero, which is worth knowing before
relying on any single review.

This document records what each finding was and what was done about it. Severity is the reviewers' own.

| First-round severity | Count |
|---|---:|
| high | 11 |
| medium | 16 |
| low | 8 |

Dispositions:

- **Fixed:** the defect is closed and at least one named test fails without the fix. Where a row says a test is
  mutation-checked, the fix was reverted and the test watched failing; for the others the test exists and that check was
  not made, or was made and not recorded here.
- **Fixed, untested:** closed by construction, and no test fails without the change. Stated as such in the row.
- **Fixed, with limits:** the reported attack is closed and a related boundary remains, stated in the row and in
  [SECURITY_BOUNDARIES.md](SECURITY_BOUNDARIES.md).
- **Mitigated:** the attack is bounded or made expensive but not removed; the remaining gap is stated.
- **Documented:** no code change; the documentation now says what is true.

## Review of the fixes

The commit that fixed the findings above was reviewed by five reviewers (engine and gate, ledger and measurement, cells, boot,
documentation accuracy), and each finding was given to a skeptic told to refute it and to default to "not real" if it could
not reproduce it. Sixty-one findings were reported and fifty-seven confirmed; several are the same defect seen from two
areas. Four were refuted (a stat that blocks on an attacker-controlled file system wedging the gate thread, a claimed
six-fold slowdown of tree building, grants below `/tmp` being redirected through symlinks, and an unreproduced timing claim).

## Review of the second round of fixes

The second commit of fixes was reviewed the same way with a smaller panel (four reviewers, one skeptic per finding): 36
findings reported, 35 confirmed, one refuted (a read error on a recovered replacement file deleting the only copy of the
floor: an unreadable file is not promoted or removed). Two were rated high, and both were the new code's own doing: a mount
table containing one byte that is not valid UTF-8 made the daemon believe there were no mounts, and the throttle wrote one
synced ledger event per throttled user, which a person with thousands of uids could turn into a stall of every `exec`.

| Severity | Area | Finding | Disposition |

| high | gate | Any non-UTF-8 byte in /proc/self/mountinfo makes discover_marks return nothing, so every later mount is ungated and the daemon refuses to (re)start | **Fixed.** The mount table is read and parsed as bytes; a table that cannot be read keeps the current marks and is retried (`a_mount_table_with_bytes_that_are_not_utf8_is_still_parsed`) |
| high | gate | Throttle summaries write one synced ledger event per throttled uid (up to 4096 plus 256 more) on the gate thread, freezing every exec for tens of seconds to minutes | **Fixed.** Summaries are a bounded number of events written with one flush (`record_degraded_many`), the throttle is one aggregate event, and the counting guard no longer freezes at 4,096 users |

## What these reviews did not cover

The reviewers read the code and ran probes; they did not fuzz the parsers, model the kernel, or test on hardware other
than the development machine. A clean list here is a statement about what was found, not a proof that nothing remains. The
list of open boundaries is [SECURITY_BOUNDARIES.md](SECURITY_BOUNDARIES.md) section 2.

## Process notes

- Each fix that closes a security property was mutation-checked where a mutation could be applied: the fix was reverted and
  the test confirmed to fail. That practice caught tests that passed without the fix they cited in the first round (a terminal
  test in a process with no controlling terminal, a TIOCSTI test whose result the kernel decided) and the second review found
  more of the same kind (a rollback test that failed before writing anything, a "keeps changing" test that never called the
  retry loop, approval tests that asserted against a decision the policy could never produce, an allow-list test that
  passed on the pre-fix code by skipping). Each was rebuilt and mutation-checked again.
- Findings that were duplicates were fixed once, at the cause.
- Decisions that changed as a result are ADR-033 to ADR-041 in [DECISIONS.md](DECISIONS.md).
